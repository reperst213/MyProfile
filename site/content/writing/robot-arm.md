**진행 상태: 완료** · 2026년 10월 컴퓨터 그래픽스 수업 과제

## 과제의 목적

하나의 큐브에 서로 다른 변환을 적용해 로봇팔의 여러 부분을 표현하는 과제였습니다. 상위 관절의 움직임이 연결된 하위 부분에 전달되는 계층 구조를 이해하고, 키보드 입력으로 로봇팔을 조작하는 것이 목표였습니다.

## 작업 내용

이 프로젝트는 컴퓨터 그래픽스 수업에서 개인 과제로 수행했습니다.

제공된 JavaScript와 WebGL 코드에는 큐브를 그리는 방식과 어깨·상완 구현이 포함되어 있었습니다. 이를 참고해 팔꿈치와 하완, 손목과 손의 변환을 완성했습니다. 각 관절이 연결 지점을 기준으로 회전하고, 부모의 변환이 자식에게 전달되도록 위치와 회전을 적용했습니다.

제공된 키 입력 예제를 참고해 나머지 관절의 조작을 구현했습니다. 자유 기능으로는 팔의 크기를 바꾸는 동작을 선택했습니다.

## 결과

키보드로 팔꿈치와 손목을 움직일 수 있는 로봇팔을 완성했습니다. 추가 기능으로 `G` 키를 누를 때마다 팔의 길이와 두께가 1%씩 커지도록 했고, 최대 크기는 처음의 두 배로 제한했습니다. 초기화하면 각도와 크기가 처음 상태로 돌아갑니다.

## 배운 점

로봇팔을 만들며 각 부품의 위치를 따로 정하기보다 **부품 사이의 관계를 먼저 생각하는 것**의 중요성을 배웠습니다. 팔꿈치는 상완의 끝에, 손목은 하완의 끝에 연결됩니다. 이 관계를 유지하는 구조에서는 팔의 각도나 길이가 바뀌어도 각 부분이 이어집니다.

처음에는 팔의 크기를 바꿀 때 각 부품의 위치와 크기를 다시 계산하려고 했습니다. 하지만 기존 구조가 이미 연결 관계를 유지하고 있었기 때문에 길이와 두께 값만 바꿔도 원하는 동작을 만들 수 있었습니다. 이를 통해 기존 구조를 이해하고 활용하는 것이 새로운 기능을 만드는 데 도움이 된다는 것을 깨달았습니다.

키보드 조작을 구현하며 입력에 따라 상태를 바꾸고, 화면 버퍼를 비운 뒤 바뀐 상태로 다시 그리는 과정도 이해했습니다. 처음에는 화면을 비울 때 정점의 색상 데이터를 담는 Color VBO가 지워지는 줄 알았습니다. 질문을 통해 화면에 표시할 픽셀의 색상을 담는 버퍼와 Color VBO가 서로 다르다는 것을 알게 되었습니다. 당연하게 지나쳤던 과정도 안쪽에서 어떻게 동작하는지 살펴보게 된 경험이었습니다.

이번 과제에서 기억에 남은 말은 교수님께서 하신 “이미 만들어진 것을 쓴다”였습니다. 마침 여러 교수님과 형에게서 ‘기여’라는 말을 들었던 터라, 이 말이 더 마음에 남았습니다. 컴퓨터공학은 수많은 사람의 기여로 만들어졌고, 우리는 그 결과를 배우고 활용하면서 새로운 기여를 하게 됩니다. 이번 과제를 통해 이미 알려진 것을 이해하고 사용할 수 있는 과정이 프로젝트에 기여하기 위한 필요조건이라는 것을 실감했습니다.
